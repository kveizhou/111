二、当前功能与必须沿用的规则
1. 支持 Source 串电阻、MOS Stack、同型 Cascode、异型 Cascode，以及确认、逐次撤销、重置和最终生成。
2. “异型”是相同 NMOS/PMOS 极性下的不同准入型号，不是把 NMOS 换成 PMOS。
3. 同型/异型、NMOS/PMOS 均在原 MOS 的 D 侧加 Cascode，原 G/S/Bulk 接线不变。
4. 确认/撤销阶段只编辑操作序列；最终 generate 才执行实际生成与所需仿真。
5. 每组 Cascode 最多 16 个自动 DC 搜索点，首个满足最低条件的点立即入选。没有完全满足的点时，从有效收敛且数据完整的点中选最佳候选。不能把执行失败或没有结果当成有效候选。
6. 多组按序累积：保留前组的接线与选定参数，在此基础上处理下一组。实验路径不以“前组重新合格”阻断后组搜索，前组检查标为 DEFERRED_TO_FINAL；最终整图 DC 仍真实报告各组未满足项。
7. 电阻调整采用当前真实 PDK/CDF 接受的参数集合，几何参数和实际网表必须生效。不能只改 r 文本、手填范围或把 CDF 接受等同于完整可靠性通过。
8. 用户不应在终端手动选阻值、尺寸或排查日志来决定 VBIAS；主流程传递输入并展示结果，搜索自动完成。真实工具错误应作为任务错误返回。
9. 此阶段不新增输出电压精度、启动时间、稳定性、PVT、面积或功耗优化验收；后续性能调优接主流程已有优化器。
10. 仅实现功能和必要正确性检查。不增加备份、容灾、安全加固、完整依赖封存、多层哈希门禁或复杂迁移。禁止使用或重新安装 Superpowers 及其别名/副本。

调用关系是 Python 启动 C++ CLI，C++ 再通过后端启动 SKILL/Python/Cadence，结果回到 C++ 判定后由 Python 汇总。
主流程至少要提供：真实源 DUT 与 Bench 的 L/C/V、cds.lib/现场环境、模型和仿真设置、选中的 MOS 与操作、会话输出位置。沿用服务器已经可用的数据和环境，具体字段以现有代码解析器为准。
异步执行 generate，转发已有进度事件及最终结果；避免在 UI 请求中阻塞数十分钟。复用主流程已有任务机制即可。

四、结果怎么交给主流程优化器
生成后的关键文件：
- work/reports/validation.txt：最终结构、电气判定、目标 CellView 与未满足项。
- work/after/core_roundtrip.scs：生成电路的实际回读网表。
- work/analysis/resolved_parameters.json：选定参数。
- work/analysis/solver_trace.jsonl（部分历史会话为 .json）：逐组搜索结果。
- 本次 resume_generate_*/run_status.json：续跑状态和输出路径。使用此次运行实际返回的位置，不按目录名猜测成功。
路径须以生成结果中 RESULT_CELL / RESULT_NETLIST / SELECTED_PARAMETERS_FILE 及 run_status.json 为准。

结果分类：
A. RESULT=EXPERIMENT_DC_PASS / EXPERIMENTAL_DC_READY=true
   已通过当前最低 DC 条件；不表示启动、稳定性、PVT 或完整可靠性已验收。
B. RESULT=OPTIMIZATION_CANDIDATE_READY / OPTIMIZATION_CANDIDATE_READY=true
   已生成有效待优化候选，但存在 UNMET_REQUIREMENTS。允许按用户要求交给后续优化器，保留未满足项及后续复验；不能在 UI 中写成“电气全部通过”。
C. RESULT=INCOMPLETE
   生成没有完成，或没有可交付的有效候选，应展示实际错误，不能拿旧结果冒充本次输出。

实验结果仍可能 READY_FOR_SIZING=false、RELIABILITY_VERIFIED=false、PUBLISHED=false；这是现有正式验收字段。主流程接入应显式支持 A/B 两种交付状态，而不是把这些旧字段改成 true。
组合测试脚本即使候选已生成，也会因电气未全过输出 COMBINED_FEATURES_TEST=INCOMPLETE / 退出 2；请区分“测试总验收”和实际 generate 的交付结果。
后续优化必须使用返回的派生电路及选中参数作为起点，不能重新绑回原始未变换 DUT。是否能修复所有未满足项，要由后续优化和真实仿真确定。

六、构建与读取入口
把压缩包上传到服务器代码父目录后：
  unzip -o st-engine-maau_source_20261019.zip
  bash st-engine-maau/scripts/build.sh --tool-only
  python3 st-engine-maau/server/site/standalone.py --help
  python3 st-engine-maau/scripts/resume_cascode_experiment.py --help

预期构建输出：built tool only: .../st-engine-maau/build/bin/st_circuit_tool
以上 help 不启动候选仿真。Linux 上用现场 C++17 编译器重编，不带本机二进制。
构建优先沿用 scripts/build.sh；当前 CMakeLists.txt 的 st_engine 显式源文件清单缺少 src/DcSolver.cpp。若接入主流程改用 CMake，需补齐该源文件并验证链接；本次仅交付原样源码，未修改构建配置。

只有需要复查现有服务器组合结果时才运行（不重新搜索）：
  bash st-engine-maau/scripts/test_mixed_cascode.sh combo-check "$st_batch/candidate_I21_xbb892w0"
